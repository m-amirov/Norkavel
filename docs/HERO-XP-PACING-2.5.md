# Norkavel — XP Pacing & Hero Progression 2.5

**Дата:** 2026-11-19  
**Статус:** QUALITATIVE_CURVE_OWNER_CONFIRMED / NUMERICAL_BALANCE_OPEN / G2-R_NOT_IMPLEMENTED

## 1. Новое решение владельца

Главный герой начинается с **уровня 1**, максимальный уровень **16**; переходы 2–16 дают **15 выбираемых игроком улучшений** (3 обычные способности × 4 + ульта × 3, открывается на уровне 5). 

**OWNER CONFIRMED 2026-11-19:** для получения нового уровня применяется **нелинейная XP-кривая**:
- первые уровни достигаются **быстрее**;
- с ростом уровня требуется **постепенно всё больше XP**, чтобы получить следующий уровень;
- повышение уровней 15→16 заметно труднее первых level-ups, не должно наступать в ранней части 50-этапной кампании при обычном прохождении;
- игрок может повторять ранее пройденные этапы ради уменьшенного, но положительного XP; поражение даёт **0 XP**. У спутников **нет XP**, их уровни покупаются вручную за золото.

**НЕ утверждены численные значения:** XP за каждую из 50 стадий, XP за боссов, множитель XP за повтор, требуемые XP для уровня 2…16, максимальная продолжительность прокачки, целевой уровень героя на конкретном этапе (включая уровень 5 к конкретной главе), тип математической функции, XP за async-PvP/idle, политика хранения XP после lvl16.

## 2. Формальный контракт кривой

Рекомендуемый data contract (имена полей PROPOSED):
- `xpToNextLevel[level]` — **добавочный** XP для перехода с `level` на `level+1`, всего **15 положительных** значений, `level=1…15`.
- `xpThreshold[level]` — **кумулятивная** величина опыта для достижения `level`, `level=1…16`. Для нового героя `xpThreshold[1]=0`; `xpThreshold[level+1] = xpThreshold[level] + xpToNextLevel[level]`.
- Для подтверждённой качественной кривой инкремент **строго возрастает**: `xpToNextLevel[level+1] > xpToNextLevel[level]` для всех `level=1…14`. Положительные и монотонно возрастающие величины — предпочтительная техническая интерпретация слов «постепенно возрастающие требования», а не утверждённый конкретный набор чисел. Необязательны постоянный процент роста/степенная/экспоненциальная функция.

На G2-R разрешено выбрать и протестировать конкретную кривую **после** сравнения симуляций. Не выдавать магические коэффициенты за решение владельца. Кривая должна храниться в versioned config, а не разбрасываться hard-coded значениями по HUD, бою и сохранениям.

## 3. Тестирование игрового темпа на пяти главах

Сравнить в детерминированной симуляции минимум три траектории:
1. **Обычное прохождение** — последовательные этапы без фарма, с ожидаемыми для контента победами/поражениями; на уровне 5 становится доступна ульта, но её открытие не гарантирует немедленной покупки улучшения.
2. **Умеренный фарм** — повторы после повышения сложности или поражения босса, каждый отдельный победный replay даёт уменьшенный XP и обычную уменьшенную gold-награду; достижение cap возможно при длительной игре.
3. **Интенсивный фарм** — много побед на уже очищенных узлах, начиная с раннего этапа; обнаружить способы слишком быстрого достижения lvl16, не запрещая подтверждённую повторяемость боёв.

Приложить таблицы/графики накопления XP и `heroLevel` по стадиям 1…50, отдельно моменты открытия ульты и получения максимального уровня, число повторов, длительность сессий и реальные временные затраты. Оценить все четыре постоянных героя и все возможные открытые составы отряда; только после этого предлагать значения.

**Балансировочные цели (PROPOSED, не численные требования владельца):** быстрый видимый первый level-up, рост затрат на позднем этапе, отсутствие необходимости гриндить ради входа в первый босс stage10 без пятого спутника, не достигать lvl16 чрезмерно рано при обычном прохождении, не создавать безвыходное состояние после 16-го уровня, обеспечить долгосрочный стимул развивать отдельных спутников за золото. Конкретные milestone-привязки и допустимый grind-time требуют отдельного review.

## 4. Награды и безопасность

- Успешный **first-clear** выдаёт обычный XP выбранному главному герою; **каждая новая** подтверждённая победа на CLEARED этапе — **уменьшенный положительный XP** по сравнению с first-clear этого этапа; поражение, незавершённая или невалидная попытка — **0 XP**.
- **Строгая идемпотентность** `attemptId`: повторный результат одной попытки не выдаёт второй XP, уровень, skill-choice или золото; разные настоящие победы могут начислять XP отдельно.
- При накоплении XP порога герой повышает уровень и получает ровно одну **самостоятельно выбираемую** модернизацию навыка (до лимитов 4/4 для обычных и 3/3 для ульты). Несколько повышений в одном settlement сохраняют все pending choices.
- При уровне **16** больше нет перехода в 17 и дополнительных upgrade choices; ранее накопленные pending сохраняются. Детали XP storage на cap пока не утверждены; интерфейс **не должен обещать следующий уровень**.
- У спутников нет XP/автоуровней, никакой общей прогрессии лагеря. Их самостоятельные уровни требуют ручной оплаты золотом. Не подменять hero XP экономики монетами.
- Версионирование наград/XP thresholds и миграция G2 save:v1 в G2-R не должны менять уже выданные first-clear награды или удалять золото/Кайра, а также внезапно создавать бонусные очки при изменении XP curve.
