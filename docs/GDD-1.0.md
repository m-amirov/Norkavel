# Норкавель / Norkavel — GDD 1.0

**Версия:** 1.0 draft · **Дата:** 18.11.2026 · **Статус:** G1 DESIGN SPECIFIED / PENDING_OWNER_REVIEW  
**Платформа:** Яндекс Игры, браузер (desktop + mobile).  
**Документ описывает проектные решения, а не реализованные механики.** Фактический исходный код Norkavel пока не содержит играбельного боя. Все числа помечены как параметры для проверки.

## 1. High concept

Норкавель — 2D фэнтезийная Idle RPG с видом сбоку. Игрок выбирает **одного главного героя**, набирает **трёх активных спутников** и отправляет команду в автоматические сражения. В PvE он помогает кликами, выбором целей и активными навыками. Между боями управляет развитием, экипировкой, расстановкой и синергиями. В рейтинговой арене сражается исключительно **асинхронно** против сохранённых команд других игроков.

**Главная ценность:** результат меняется от осмысленной сборки, а не только от числа кликов. Ручная активность даёт пользу, но не становится обязательной для idle-прогресса.

**Целевая сессия (гипотеза):** первый бой за 60–90 с от входа; обычный визит 3–8 минут, с возможностью оставить PvE автобой. Проверять измерениями и тестами на новых игроках.

**Важное ограничение:** игра самостоятельная, механики и контент других наших игр не использовать как исходный материал. **Вся мобильная игра работает только в landscape; это обязательное решение владельца, не гипотеза.**

## 2. Игровой мир (предлагается)

Норкавель — мир, разделённый Разломом. Пограничные поселения защищаются от созданий, пришедших из «трещин». Герой — Страж, ведущий небольшой отряд и постепенно восстанавливающий проходы между регионами. История подаётся через короткие описания глав, появления боссов и биографии спутников; не мешает быстрому повтору боёв.

Тон: приключенческое фэнтези, загадочность, яркая магия, умеренная тёмная атмосфера. Лор и имена регионов не канон, пока не утвержден Art/Lore Gate.

## 3. Core loop и метацикл

**Основной цикл:**
1. Игрок формирует героя + 3 спутников: роли, фронт/тыл, навыки, экипировка.
2. Выбирает этап кампании; автосимуляция начинает боевые действия.
3. Наблюдает HP, цели, статусные эффекты; в PvE кликает по врагу, применяет 2 активных способности или включает auto-cast.
4. Бой заканчивается победой или поражением с отчётом о причинах.
5. За победу начисляются награды; при поражении доступен бесплатный retry и подсказка, что перестроить.
6. Улучшение героя/спутников меняет потенциал или тактику; цикл повторяется на новых этапах/боссах.

**Метацикл:** открытие классовых ветвей, коллекция спутников, получение экипировки, достижения, ежедневные задания, PvP-лиги и сезонные рейтинги. Пассивный доход не должен подменять игру только ожиданием таймера.

**Основные действия с обратной связью:**

| Ввод | Предусловие | Реакция | Ограничение |
|---|---|---|---|
| Начать PvE | доступен этап и готов отряд | сцена боя, читаемые юниты и таймер | нельзя повторно списывать ресурсы |
| Тап по врагу | PvE, цель жива, cooldown готов | выбор цели и вспомогательная атака | debounce и лимит ручного DPS |
| Навык 1/2 | PvE, достаточно энергии, cooldown = 0 | урон/контроль/бафф и FX | один каст на событие |
| Auto-cast toggle | PvE | навыки используются по заданному приоритету | равный базовый шанс прогресса |
| Сменить спутника | вне боя | пересчёт синергий и ролей | не меняет уже начатый рейд |
| Сохранить защиту | online PvP доступен | версия состава отправлена на доверенный backend | авторизация, проверка параметров |
| Начать PvP | snapshot и противник валидны | сервер симулирует матч и возвращает replay | PvP без кликов и WebSocket |
| Повторить этап | после поражения | возврат к этапу, свежий deterministic seed | без дубликата наград |

## 4. Главный герой

Один главный герой обязателен во всех боях. При старте игрок выбирает **один из четырёх классов** (состав предлагается). У каждого базовая автоатака, 2 активных PvE-скилла, пассивка и 3 направления талантов после G2.

| Класс | Идентичность | Активные навыки | Контрсценарий |
|---|---|---|---|
| Воин | фронтлайн / защита союзников | Щитовой удар (прервать), Стойкость (сократить урон) | уязвим против длительного магического AoE |
| Маг | сильный AoE / стихии | Огненная дуга (горение), Ледяной круг (slow) | требует защиты от фокуса |
| Ассасин | burst / приоритет слабых целей | Теневой рывок (смена цели), Ядовитый клинок (DoT) | контрится групповым контролем |
| Следопыт | дистанционный DPS / метки | Меткий выстрел (single target), Ловушка (slow) | зависит от защиты фронта |

**Выбор класса:** у выбранного класса постоянная история развития; механизм его последующей смены остаётся OPEN, нельзя удалять персонажа/покупки без отдельного решения. G2 строится на одном классе, другие — G4.

**Характеристики:** HP, ATK, DEF, скорость атак, критический шанс, критический множитель, сила лечения, устойчивость к статусам. Статистики должны иметь объяснение в UI; не вводить десятки скрытых показателей.

## 5. Спутники и стратегия

В бою всегда **три спутника** рядом с главным героем. В полном контентном объёме предлагается 12: по 3 защитника, damage dealer, control и support. До G2 достаточно 3 различных спутников, а для теста стратегической свободы — 1 альтернативный персонаж.

Для каждого спутника: класс роли, auto attack, 1 auto-cast умение, 1 пассивка, tag синергии, уровень; позднее ранг/экипировка. У игрока должны быть бесплатные способы их открытия, без обязательной покупки редкого персонажа.

**Позиции:** фронт / тыл, без сетки и без свободного pathfinding. Герой занимает допустимую позицию класса. Защитники перехватывают типичные ближние атаки; дальние/AoE способны атаковать тыл по явным правилам. При гибели фронта тыл становится целью по обычному приоритету. В PvP весь состав и его политика целей фиксируются перед боем.

**Шесть предлагаемых синергий:**

| Теги | Комбинация | Игровая реакция |
|---|---|---|
| Пламя + Пепел | Зажигание | бонус к урону по горящим врагам |
| Мороз + Гроза | Сковывание | повышенный контроль замедленной цели |
| Страж + Свет | Защитник | временный групповой барьер |
| Тень + Метка | Добивание | усиление одиночного burst по помеченному |
| Яд + Кровь | Изнурение | ограниченный суммарный DoT |
| Отвага + Лечение | Ответ | бафф после спасения союзника с малым HP |

Каждая синергия должна отображаться прямо в составе отряда: условие + итог, а не скрытый multipliers. Её эффект подтверждается deterministic A/B тестом. Не должно быть одной универсально лучшей команды для всех боссов.

## 6. Боевые правила

**Бой — детерминированная симуляция с fixed tick.** Предлагается tick=50 мс, то есть 20 ticks/s. Рендер не влияет на математику. При одинаковых версиях баланса, seed, составах и начальном состоянии итог и журнал событий полностью совпадают.

Стартовая формула урона (баланс-гипотеза):

    damage = max(1, round(ATK * skillMultiplier * 100/(100+DEF) * affinity * critModifier))

ATK и DEF выбираются по типу урона, округления и порядок применения статусов фиксированы. Базовый критический шанс предлагается 5%, множитель — 1.5. Случайность только из детерминированного PRNG и seed, **никогда** из Math.random в критическом игровом пути. Хранить баланс-версию в replay. Для сложных статусов фиксировать порядок: истечение эффектов → action timers → выбор целей → queue действий → урон/лечение → смерти/триггеры → win/fail check → запись событий.

**Ограничение:** PvE max 90 с; PvP max 60 с (предлагается). PvE победа: все враги уничтожены; поражение: все союзники погибли либо истёк таймер. Для PvP симультанная гибель и равное соотношение HP считаются ничьей без победного рейтинга атакующему; правило пересматривается до релиза.

**Boss design:** видимый телеграф 0.7–1.5 с перед сильной атакой; у игрока есть проверяемое противодействие (прерывание, щит, позиция). Контроль босса ограничивается diminishing returns; нельзя бесконечно станить. Attack/hit/death/revive события никогда не должны приводить к повторному award.

## 7. Кликер и активные навыки

Клик по живому врагу выбирает цель и при готовности запускает дополнительную атаку героя. Удержание заряжает сильный удар; это опциональная механика после проверки частоты/доступности. Есть две явно видимые кнопки активных навыков, cooldown/energy, горячие клавиши и touch. Auto-cast — доступная альтернатива обязательным кликам.

**Баланс-контракт:** целевой вклад ручного кликанья не более 15–25% от общего DPS при сравнимой силе состава. Это стартовый диапазон, проверяемый симуляциями. Input spam блокируется по cooldown, не ускоряет серверное PvP, не создаёт endless rewards и не ломает FPS. При низкой частоте кадров и pause/resume число действий должно оставаться корректным.

**В PvP ручные действия полностью отключены.** Игрок влияет на PvP только выбором класса/состава, позиции, скиллов и AI priorities до начала.

## 8. PvE-кампания, проигрыш и исследование мира

Предлагаемый объём: 5 глав по 10 этапов = 50. Этап состоит из 1–3 волн; этап 10 каждой главы — босс со своим паттерном и counterplay. Глава 1 учит атаке и навыкам; глава 2 — роли; глава 3 — статусы/синергии; глава 4 — позицию и приоритет; глава 5 — комбинации и сложные боссы.

Не превращать все этапы в противников с большим HP. Каждый новый блок должен открывать механику, связанное решение, а затем повторение в сочетании с уже изученным.

Поражение не блокирует игру: **бесплатный retry**, состав/экипировка остаются неизменными до смены игроком, победные награды предыдущих этапов сохраняются. После поражения показывать анализ причины и контрмеру, а не предложение заплатить.

**G2 First Playable:** 1 класс главного героя, 3 спутника, 3 врага, 1 босс, 1 реальная синергия, 1 возможность смены позиции/тактики, автоатака, клик и хотя бы 1 активный навык, победа/поражение/retry с живой 2D-сценой в браузере. Временные изображения допускаются только для проверки mechanics, не проходят G3.

## 9. Прогрессия и внутриигровая экономика

Три оси роста:
- Герой: уровень, 4 слота экипировки, навыки и позднее ветви талантов.
- Спутники: коллекция, уровни, ранги/осколки и их индивидуальные способности.
- Аккаунт: открытия глав, достижения, исследовательские пассивные улучшения.

Предлагаемые ресурсы: золото (базовые апгрейды), материалы (снаряжение), осколки спутников (их ранг). Редкость — источник вариантов билдов, не обязательный paywall. Таблица источников, sinks, цены и план прогрессии 1/3/7/14 дней составляются перед G3; не заявлять сбалансированность до симуляции.

**Idle:** ограниченная выплата стандартных PvE-ресурсов максимум за 8 часов офлайна (предлагается); без автоматического выигрыша в PvP, создания премиальных предметов и сезонного рейтинга. Запрещено повторное начисление при reload/rollback и накрутка через перевод часов. Доверенный timestamp нужен для конкурентного прогресса.

## 10. Асинхронная PvP-арена и рейтинг

Игрок сохраняет команду защиты. Атакующий выбирает из предложенных соперников и начинает короткий бой с их **сохранённым snapshot**, защитнику не нужно находиться онлайн. Состав включает уровни, навыки, priority rules и версию баланса. PvP-бой — полностью авто, сервер возвращает результат и воспроизводимые события.

**Нельзя считать арену реализованной без доверенного backend либо эквивалентного проверяемого server authority.** Браузер не должен иметь право прислать «я победил», произвольное количество рейтинга или валюту. Обязательны проверка состава, auth/identity, seeded deterministic replay, идемпотентные награды, idempotency key, rate limits, защита от replay/clock tampering, управление сезонами и хранение только минимальных данных.

Если backend недоступен, показать честное «Арена временно недоступна», не подменять живые рейтинговые команды ботами без маркировки. Возможно отдельное **PvE тренировочное** сражение с AI-защитой, но не как fake PvP.

Предлагается 5 лиг, сезон 14 дней, 3 выбора близких оппонентов, seasonal reset с переносом косметической истории. Точная формула рейтинга и антиабьюз требуют независимого баланс- и security-дизайна перед G4. Leaderboard показывает только проверенные сервером результаты.

## 11. Retention: задания, достижения, сезоны

Предлагается 5 daily quests, среди них: победить PvE этап; усилить снаряжение; применить синергию; победить босса; сыграть PvP. Если online недоступен, PvP-квест меняется на PvE-альтернативу и не превращается в невыполнимый ежедневный список. Везде есть reset policy, idempotency и явный progress.

Предлагаются 20 достижений по категориям: кампания, классы/спутники, синергии, боссы, арена. Награды не дают покупки рейтингового превосходства. Сезонные таблицы лидеров зависят от server-derived ranking и правил на одинаковые очки.

## 12. UX и доступность

**Окончательно утверждено:** вся мобильная версия **только в альбомной (landscape) ориентации** — бой, меню, карта, герои, арена и остальные экраны. Портретную компоновку интерфейса не разрабатывать. При вертикальном положении устройства отображается отдельный полноэкранный экран «Поверните устройство», который не даёт начать бой или взаимодействовать со скрытой игровой сценой. По возвращении в альбомную ориентацию восстанавливается прежний экран и корректное состояние игры, без сброса/дублирования наград. Запрос системной блокировки ориентации можно делать только как best-effort при доступной поддержке браузера; отсутствие API или отказ (в том числе на iOS) **не является ошибкой** — работает экран поворота. Союзники слева, враги справа, вверху текущая волна/таймер, внизу две кнопки активных навыков и статус энергии, безопасное место под pause/retry. Боевую сцену нельзя перекрывать бесконечными цифрами или мыльными вспышками.

Экраны: стартовый выбор класса, карта этапов, бой, результат, отряд, коллекция, экипировка/навыки, арена, ежедневные задания/достижения, настройки. UI обязательно поддерживает touch и мышь; клавиатура — для desktop. Читаемость и интерактивные области проверяются на реальных **альбомных** мобильных viewport (например, 640×360, 667×375, 844×390, 915×412), планшетных и десктопных размерах; вертикальные 360×640, 390×844, 768×1024 и 1024×1366 проверяются **только как экран поворота**, а не как игровой UI. Учитывать safe area/вырезы, высоту доступного viewport, изменение ориентации во время боя, уменьшение эффектов, выключение звука и корректные pause/resume/reload.

Не требовать постоянного интернет-соединения для локального G2 PvE, но офлайн-запуск всей игры не является обязательным требованием.

## 13. Art Direction / audio

Финал — hand-painted 2D-fantasy высокого качества: читаемые ключевые персонажи с различимыми классами, многослойный фон, плавные атаки и VFX, телеграфы боссов. Примитивная графика может быть внутренним прототипом, но не утверждённой визуальной концепцией и не вертикальным срезом. Подробнее — ART_DIRECTION-0.1.md.

Каждый производственный art item имеет лицензию/происхождение, оригинал, version/hash, usage mapping и независимый visual QA. Система анимаций выбирается на основе реальной производительности/размеров, без выдуманных FPS доказательств.

## 14. Монетизация (не на G2)

**Предлагается:** добровольная rewarded-реклама за ограниченные PvE-ресурсы и косметические IAP после проверки реального SDK и платформенных правил. Никаких обязательных рекламных просмотров для прогресса, платных побед, непрозрачных лутбоксов и pay-to-win рейтинга. Если будут IAP, выдача должна подтверждаться авторитетной стороной, а не только локальным сохранением.

Пока арена не проверена, платёжные награды и реклама отключены.

## 15. Архитектура и технические риски

- **Ludory Core:** metadata, lifecycle, state/snapshot. Подключение источников по pin SHA; не объявлять Studio trusted-origin по одному manifest.
- **Norkavel domain:** детерминированные боевые правила (pure simulation), баланс-данные, AI priorities, статусы, replay.
- **Renderer:** Phaser или другой проверенный game-owned 2D UI после compatibility proof; наличие Ludory Phaser adapter само по себе не доказывает рабочий autobattler.
- **Connect:** Yandex SDK и cloud saves на реальных контрактных API в отдельном gate; Core smoke не эквивалентен Connect.
- **Server:** authority для PvP, season rankings и rewards; конкретный hosting/security stack ещё OPEN. Не нужен для базового локального PvE.
- **Saves:** schema-version, migration, повреждение/старые версии, no double-award. Исторические Ludory narrative saves не копировать.
- **Perf:** fixed-step engine независим от визуальных кадров, pause safe, cap VFX, browser QA по устройствам.

Нельзя считать Ludory Studio one-click генератором готового real-time autobattler: подтверждённые платформенные возможности могут быть преимущественно narrative-oriented. Нужен отдельный G2 integration proof.

## 16. Гейты, целевой объём и критерии

| Gate | Содержание | Требуемые факты |
|---|---|---|
| G0 | Подтверждение жанра/платформы/героя/отряда/PvP | решения владельца |
| G1 | GDD 1.0 + трассировка требований + техконтракт | owner design review |
| G2 | 1 герой, 3 спутника, 1 синергия, 3 врага, босс и цикл победы/поражения/retry | реальный браузерный smoke, deterministic tests |
| G3 | законченная сцена с настоящим art, анимацией, audio/UI и game feel | визуальное QA + наблюдаемый playtest |
| G4 | 4 класса, 12 спутников, 5 глав/50 этапов, 5 PvP-лиг, 20 достижений, daily | контент reachability + проверенный backend |
| G5 | тесты, реальные игроки, разные браузеры, устранённые P0/P1 | exact-SHA QA и реальный playtest |
| G6 | локальный релизный кандидат для Яндекса | ZIP receipts, verified source, rights + platform preflight |
| G7 | реальная приемка платформой и отдельное разрешение владельца | официальные факты и owner approval |

**G2 acceptance:** (a) бой реально запускается и завершается, (b) четыре союзника и хотя бы один враг видны, (c) смена состава/позиции может изменить исход, (d) click/skill оказывает видимое измеримое влияние, (e) same seed+data => same result, (f) pause/retry не даёт двойных наград, (g) босс даёт ясный телеграф, (h) touch/desktop управление протестировано в **landscape**, (i) онлайн-арена не имитируется, (j) при портретной ориентации работает только экран поворота, во время перехода не происходят скрытые действия/двойные награды, после возврата в landscape игра продолжает корректно.

**Kill/retune signals для прототипа:** бой не даёт игроку понятного выбора; тактика и синергии не меняют результат; обязательны сотни кликов; босс атакует без предупреждения; мобильная сцена нечитабельна. Все утверждения об удовольствии игроков требуют **реальных участников**, не AI оценок.

## 17. Открытые вопросы перед production

1. Можно ли менять выбранный класс после обучения, или он фиксируется на весь аккаунт?
2. Арт-атмосфера: светлое героическое, сумрачное или тёмное фэнтези?
3. РЕШЕНО (owner 2026-11-18): игра на мобильных устройствах работает исключительно в landscape; портрет — только экран с просьбой повернуть устройство.
4. Разрешён ли отдельный сервер для честной PvP-арены, если native Yandex API не обеспечивает необходимой authority?

До ответов решения обратимы: баланс отделён от кода, палитра не закодирована, UI адаптивен, PvP через interface, не замаскированный под готовую систему.
