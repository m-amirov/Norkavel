## 1. Что принято, а что предложено

**OWNER_CONFIRMED:** герой один из четырёх, навсегда выбранный; heroLevel 1…16; XP только за победы, replay XP меньше first clear, defeat XP 0; нелинейно возрастающая цена следующего уровня XP; по одному самостоятельному улучшению на уровнях 2–16 (3×4 обычных + 3 улучшения ульты, которая открывается на lvl5). У каждого из 5 спутников только собственный уровень, приобретаемый вручную за золото, companion XP нет. Ровно 50 этапов в пяти главах, боссы 10,20,30,40,50, повторные победы дают уменьшенное золото, first-clear milestones только однажды.

**ЗДЕСЬ ПРОЕКТНОЕ ПРЕДЛОЖЕНИЕ:** абсолютные XP и золотые выплаты, 40% replay XP, 50% replay gold, бонусы на боссе, формулы стоимости уровня спутника, сценарии повторов и формулы XP-кривой. **Это не owner-confirmed цифры и не production runtime config.** Ни новые боевые персонажи, ни 50 encounters ещё не реализованы. Не распространять баланс как PASS для 4 разных героев или живой аудитории.

## 2. Кандидатные формулы

```text
hero level cap: 16; starts at level 1
k = heroLevel - 1  (k = 0..14)
xpToNext(heroLevel) = 40 + 6*k + ceil(13*k*k/4)

stage = 1..50
chapter = ceil(stage / 10)
boss = stage % 10 === 0

firstClearBaseXP = 12 + 3*stage
firstClearBaseGold = 32 + 8*stage
bossFirstClearBonusXP = boss ? 25*chapter : 0
bossFirstClearBonusGold = boss ? 80*chapter : 0
firstClearXP = firstClearBaseXP + bossFirstClearBonusXP
firstClearGold = firstClearBaseGold + bossFirstClearBonusGold

repeatVictoryXP = max(1, round(firstClearBaseXP*0.40))
repeatVictoryGold = max(1, round(firstClearBaseGold*0.50))
defeatXP = 0
companionUpgradeGoldCost(currentLevel) = 45 + 12*currentLevel + 3*currentLevel^2
```

**Важно:** бонус босса начисляется только при first-clear и не попадает в repeat reward. XP-кривая strictly increasing в интервалах 1→2…15→16. Спутникам XP не начисляется. Цена `companionUpgradeGoldCost` применима **только к добровольной покупке** одного уровня одного открытого спутника; приведённая модель не утверждает его максимальный уровень.

## 3. Сценарное моделирование

Симуляция считает **только успешные бои**, с детерминированной выдачей XP и золота; не моделирует урон, фактическое время боя, шансы победы, покупки рекламы/IAP, ежедневные задания, idle-доход или PvP. Нет скрытой автоматической прокачки спутников. Нельзя делать выводы о проходимости боссов только по этим цифрам.

- **Normal:** 50 first-clear, ни одного повторного боя.
- **Moderate:** 50 first-clear + **одна победа повторно каждые 3 успешно пройденных этапа** (этапы 3, 6…48), всего 16 replay.
- **Intensive:** после первого прохождения **каждый этап повторяется ещё 3 раза**, всего 150 replay.

|---|---:|---:|---:|

**Аналитическая особенность:** при интенсивном фарме lvl16 достигается на этапе 33 после **132 побед (33 first-clear + 99 повторных)**. Это не мгновенный exploit: игрок должен выиграть дополнительные бои. Оценка затраченного времени пока **НЕ измерена**: существующий технический G2 (2 стадии) не равен длительности 50 новых эпизодов. После капа модель суммирует XP для анализа экономики; игра **не должна обещать ещё один уровень или выдавать лишний выбор**.

**Контроль stage 10:** без фарма герой уже lvl5 к этапу 9 (243 XP), поэтому ульта доступна **до** первого сюжетного босса. Это не доказательство его боевой проходимости всеми четырьмя героями и первым набором спутников — отдельный G2-R balance gate.

**Ограничения модели:** нет расходов на экипировку/вспомогательные системы, ежедневных наград, пассивного дохода, монетизации и ставок PvP. Нельзя делать вывод, что финальный контент проходим с указанными уровнями спутников: ещё нет утверждённых stats/HP/ATK/защит/скиллов 50 этапов и симуляций побед.

## 6. Балансировочные риски и решения

1. **Риск преждевременного max hero при фарме:** intensive получает lvl16 к stage33, но после 132 реальных побед. Это допустимо как платёж игровым временем, однако необходимы реальные замеры длительности/доступности автоматических побед. Нельзя скрытно запрещать replay: они утверждены владельцем.
2. **Риск перегрузки золота спутников:** при равномерной прокачке пяти героев нормальная кампания обеспечивает примерно level11–12 без иных наград. Должны быть доступны жизнеспособные выборы нескольких троек для boss 20/30/40/50; combat stats ещё отсутствуют.
3. **XP на боссе:** stage10 и каждый десятый получают отдельный first-clear XP bonus; важно не сдвигать обязательный unlock ледяного контролёра до победы stage10, а увеличение XP не должно само выдавать его.
4. **Прогресс после cap:** игрок продолжает получать реальные нормальные/повторные gold rewards, улучшать спутников и проходить этапы. Уровень17, новый skill choice и прогресс-бар «до17» запрещены; сохранение избытка XP как статистики — отдельное решение.
5. **Надёжность сохранения:** отдельно `firstClearClaim(stage)`, `rewardClaim(attemptId)` для XP/золота и `purchaseClaim(purchaseId)` для уровня спутника. Один результат или покупка не должны повторно начислять XP или списывать золото. Этот симулятор **не реализует** транзакционную защиту в игровом runtime.
6. **Баланс четырёх героев:** одна XP-кривая — допущение для аналитического расчёта. Нельзя заявлять, что каждый из 4 героев достигает той же стадии при одинаковом числе попыток: потребуются четыре уникальных hero kit и модели побед/поражений.
7. **Реальные спрайты/UX:** 50 stage backgrounds и 5 chapter maps не созданы; численный баланс не снимает художественные и browser release gates.
