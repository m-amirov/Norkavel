# Norkavel — автономный цикл Codex / WFA / Ludory

**Статус:** проектный порядок работы · 2026-11-19.  
**Главная цель:** пользоваться **короткими командами**, не переписывать ГДД в каждом промте и не создавать параллельную систему управления проектом.

## 1. Единая точка входа

Из корня репозитория Codex получает обычное поручение «Продолжай Norkavel» или «Выполни следующую задачу». Порядок действий определяется настоящим `AGENTS.md` и этой инструкцией, а не новыми длинными пользовательскими промтами.

Перед любыми изменениями агент самостоятельно:
1. Изучает `AGENTS.md` → **эту инструкцию** → [очередь задач](TASK_QUEUE.md) → [фактический статус](PROJECT_STATUS.md), `git status`, `git log -1`, фактический код и тесты.
2. Открывает **только относящиеся к задаче** нормы из `docs/GDD-1.1.md`, `docs/DECISIONS.md`, `docs/ACCEPTANCE.md`, проектные технические и художественные спецификации. `docs/GDD-1.0.md` — история, не текущая норма.
3. Выбирает **первую доступную** задачу `READY` из `TASK_QUEUE.md`, у которой удовлетворены зависимости. Если текущая задача блокирована внешним решением — отмечает блокер с доказательством и берёт следующую независимую `READY`, **не выдумывая решение владельца**.
4. Выполняет **один законченный и проверяемый срез** до соответствующих тестов, вместо масштабного «рефакторинга всей игры». Если задача уже реализована, это требуется **доказать исходниками и тестами**, а не полагаться на старое описание или отчёт.
5. Обновляет статусы и доказательства, переносит подтверждённую работу в `origin/main` по правилам WFA, а затем коротко сообщает результат.

**Не нужно** ждать ещё одного длинного задания, если следующая задача и acceptance уже заданы в проекте. **Не нужно** переписывать тысячи строк из GDD в одно сообщение.

## 2. Разделение полномочий: кто чем управляет

| Источник | Ответственность | Приоритет и граница |
|---|---|---|
| Владелец, `docs/DECISIONS.md`, текущий `docs/GDD-1.1.md` | **Что строим**: утверждённый дизайн, явные запреты, OPEN | Не изменять CONFIRMED без владельца; поздние решения имеют приоритет над устаревшими предложениями |
| Фактический код и **проверенные** контракты `vendor/ludory` | **На чём работает игра**: lifecycle, save, Core/Studio/Runtime/Connect/Release | Не выдумывать API. Pinned Core **не означает** Studio trust, live Connect или готовый release |
| `vendor/workflow-for-agents` | **Как выполнять**: задача → подходящие Skills/роли → проверки → evidence → main | Не изменяет игровой дизайн, не заменяет движок и **не запускает агентов сам по себе** |
| `docs/TASK_QUEUE.md` | **Что делать следующим**: один активный приоритет, зависимости, выход и блокеры | Рабочая очередь, не источник новых игровых требований |
| `docs/ACCEPTANCE.md`, `docs/PROJECT_STATUS.md` | **Как подтверждаем** и что реально сделано | `PASS` только по тестам/артефактам на exact SHA; `NOT_RUN` честно фиксируется |

При противоречии: уточнить действующую owner-confirmed норму по ID решения, затем проверить реальный Ludory контракт и код. Если правила несовместимы — записать **BLOCKED_CONTRACT_CONFLICT** с файлами/строками, не устранять конфликт молчаливым изменением игры или WFA.

### WFA и Ludory без дублирования

- WFA-процесс: `vendor/workflow-for-agents/playbooks/game-production.md`, роли `agents/developer.md`, `agents/reviewer.md`, `agents/qa-engineer.md`; для больших задач `skills/core/task-planning/SKILL.md`, затем **минимальный набор по задаче**.
- Подходящие Skills: `skills/domain/gameplay-design/SKILL.md`, `skills/gamedev/workflows/game-docs/SKILL.md`, `skills/testing/regression-testing/SKILL.md`, `skills/testing/browser-qa/SKILL.md`, `skills/domain/game-content-qa/SKILL.md`, при арт-задачах `skills/domain/production-art/SKILL.md`. Проверять наличие у конкретного pinned WFA commit.
- Ludory: читать **действительные** файлы/экспорты из `vendor/ludory`; изменения исходного фреймворка — в его репозитории, только если там действительно root cause и это совместимо с другими играми. Norkavel-specific логика должна оставаться в Norkavel.
- Сначала `git submodule update --init --recursive`, затем проверка закреплённых SHAs и доступности файлов. В CI Skills ставятся **в эфемерный workspace**. Наличие подмодуля и зелёный CI **не доказывают**, что Skills активированы в локальном Codex. Выбирать и устанавливать Skills **только project scope**, по реальной необходимости, без глобальных изменений.
- Если Codex поддерживает настоящие независимые роли, можно запустить их по WFA; каждый отдельно пишет evidence. Если независимых исполнителей нет, делать self-review, статус `SELF_REVIEW`, **никогда не писать `INDEPENDENT_REVIEW_PASS`**.

## 3. Цикл для каждой задачи

**DISCOVER → PLAN → IMPLEMENT → VERIFY → REVIEW → INTEGRATE → HANDOFF.**

1. **DISCOVER:** фактические файлы/контракты/тесты, последний `main`, актуальные зависимости. Не предполагать структуру проекта по прежним промтам.
2. **PLAN:** определить границы среза, ссылки на решения, источники риска, acceptance IDs; применять WFA task planning, если высокий риск/несколько модулей/миграция. Не тратить новый промт на повторное согласование уже подтверждённого.
3. **IMPLEMENT:** минимальные изменения, никакого беспричинного архитектурного переписывания. При баге исправить первопричину и regression. Соблюдать schema migration, idempotency, landscape-only, async-only PvP.
4. **VERIFY:** `npm run check`, `npm run smoke:ludory` и при UI/боевых действиях `npm run test:browser`; при экономике `npm run balance:test` и `npm run balance:simulate`. Это ориентир; запускать только то, что существует и применимо, фиксировать exit codes и конкретные результаты. Экономическая модель — **CANDIDATE**, не обязательные gameplay-значения.
5. **REVIEW:** провести предметную проверку изменений, негативные кейсы и сохранения; если был реальный независимый агент — приложить его исполненный receipt. Отсутствие отдельного агента — не основание для выдуманного PASS.
6. **INTEGRATE:** main-first по WFA: работать в `main`, если доступно и разрешено защитой. Если пришлось создать ветку, пройти проверки, объединить разрешённым способом и удалять лишь свои интегрированные временные ветки. **Не force-push**, не обходить branch protection/CI. Подтвердить `origin/main` exact SHA; при невозможности указать `BLOCKED`.
7. **HANDOFF:** обновить только нужные `docs/TASK_QUEUE.md`, `docs/PROJECT_STATUS.md`, `docs/ACCEPTANCE.md` и, если реально возникло новое решение, `docs/DECISIONS.md`. Не дублировать весь GDD. Для DONE/VERIFIED — источник, тест, SHA, ссылка на CI; в ответе 2–5 предложений: итог, проверки, блокер/риск, следующая задача.

**При защите main:** не создавать ложный DONE. Если CI ещё выполняется, писать `AWAITING_CI` и не объявлять завершение, даже если автор локально видит PASS.

## 4. Разрешённая автономность и обязательные стоп-гейты

Можно самостоятельно: изучать репозиторий, выбирать независимую READY-задачу, готовить рабочий код и тесты, исправлять regression, обновлять документированные статусы и пользоваться подтверждёнными API Ludory.

**Нужно решение владельца перед:** изменением OWNER_CONFIRMED механики; постоянным назначением герою неизменяемой идентичности при миграции; удалением пользовательских сохранений; превращением **чисел-кандидатов** Economy Balance 0.1 в окончательный live-баланс; подключением платных сервисов/секретов; публикацией, платежами и рейтингами с недоверенным серверу состоянием; принятием художественных активов и лицензий.

Блокер не равен остановке всего проекта: отметить, чем он вызван, продолжить другую допустимую READY-задачу. Но **не имитировать готовность**, временными артами не закрывать G3, legacy G2 CI не считать G2-R, не выпускать игру до настоящих gates G5–G7 и отдельного owner approval.

## 5. Пример обычной команды

`Продолжай Norkavel по AGENTS.md. Выполни следующую READY-задачу, проверь и интегрируй в main.`

Этой команды достаточно для выбора текущего шага, потому что подробности хранятся **в репозитории**. Устное «продолжи» должно работать в Codex, открытом в корне Norkavel: агент начинает с `AGENTS.md` и `TASK_QUEUE.md`.

**Состояние на 2026-11-19:** автономная инструкция и очередь — документация, **не развернутый планировщик и не доказательство запуска Codex/субагентов**.
